# Keel — 官网

六个真实页面,不是一屏长滚。静态 HTML,无构建步骤。

```
site/
  index.html          首页:税不进钱包,进仓位
  how-it-works/       六步:从一笔交易到一次分红
  economics/          两层钱:税 80/20,收益 60/40
  vault/              金库读数(未部署时显示空,不显示假数据)
  risks/              会出什么错
  verify/             怎么自己复现全部数字
  assets/base.css     设计系统
  assets/site.js      导航状态、滚动显现、canvas 工具
```

## 视觉来源

配色与字体取自 `trystudio.ai` 的系统:近黑底 `#141414`,整套层次由白色的不同透明度构成,
颜色只留给语义(正 `#5bbf9a`、负 `#d96a6a`、警 `#d9b45b`、信息 `#6aa3d8`)。Geist Sans /
Geist Mono。技术小标签用 `//` 分隔。

两处**故意不同**:

- **它是单页长滚,这里是六个真实路由。** 深链、后退键、分享单页都必须成立。
- **它的插图是 AI 生成的照片(`/gen/batch-27-v6-warm/...`),这里全部是 canvas 画的。**
  这个产品的主体是刻度、仓位和一个时钟,画出来比拍出来准确,而且每一个数字都能对上合约。

## 每一页都有一个把机制画出来的图

不是装饰。首页是五分钟结算周期与仓位两条腿;机制页是一笔税走完六段路,以及循环建仓与闪电贷
建仓的成本对比;经济页是两层钱各自的流向;风险页是四个杠杆档位各自离清算多远;金库页是抵押与
负债的实际比例。每个图都配一段完整的文字描述,读屏与不开 JS 时不丢信息。

## 验证

```bash
PLAYWRIGHT=<path>/node_modules/playwright/index.mjs node tools/qa-site.mjs
```

真浏览器渲染两个视口(1440×900 与 390×844),截图存 `.qa/`,并检查**几何而非存在**:
h1 是否被 sticky 导航压住、页面是否横向溢出、视口内的 canvas 是否真的画了东西、底色与字体
是否生效、前两屏里有几个 section。

它抓到过三个真问题:移动端导航把每页撑宽 140px;hero 里两段文字因写死偏移而重叠;以及风险页
的图注写了 "drag to compare",而那个 canvas 根本不能拖——**页面上不能出现不存在的功能**。
