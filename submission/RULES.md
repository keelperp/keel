# The ten rules, one row each

Full self-audit with reasoning: [`../AUDIT.md`](../AUDIT.md). This page is the summary and the
proof for each line. Every test named here exists in the repository, and every one of them
is green except the four in `LeverVaultPosition.t.sol`, which the whole suite skips without an
archive RPC — disclosed in the Rule 006 row below and counted as passing nowhere on this page. It
is a self-audit, not a third-party audit, and there has been no third-party audit.

Two facts frame everything below, and neither is softened anywhere on this page.

**No token has been launched, on any chain.** The factory is deployed on BNB Chain and on BSC
testnet, but nothing has gone through the VaultPortal, so no vault exists yet either. Every
launch parameter is written down in `LAUNCH.md` and none of it has been executed.

**No vault can be created on BSC testnet at all**, so there is no testnet end-to-end run to show
you. The reason is a missing market, not a missing config, and it is measured rather than assumed:
the build path *must* flash-borrow, because Venus checks collateral before borrowed funds become
collateral — and BSC testnet's PancakeSwap V3 is empty. `getPool` returned the zero address for
32 WBNB pairs across 4 fee tiers, and no `PoolCreated` event appears in the last 40,000 blocks.
We cannot build a pool ourselves either: both test USDT contracts gate `mint()` behind `Ownable`
with a third party as owner. Venus itself *is* live on 97 — vBNB listed, 16.3 tBNB borrowable —
and its collateral factor is 70% against mainnet's 80%, which `_cf()` reads from chain, so the
health floor would simply bind leverage near 2.4x there. That last part is the floor working, not
a fault; the V3 line is the hard blocker.

## Build

Solidity 0.8.26, Cancun, optimizer 200 and `bytecode_hash = "none"` are pinned in `foundry.toml`.
`via_ir` is **not** pinned: the file carries no `via_ir` key at all, so via-IR is off by upstream
default rather than by our choice, and a change to that default would retarget the bytecode
silently. Everything else in the build is nailed down; that one is not.

The table below is what this repository compiles to today, not what is on chain — see Deployed.

| Contract | Runtime | Margin to EIP-170 |
|---|---:|---:|
| `LeverVault` | 23,193 | 4,994 |
| `LeverVaultFactory` | 7,745 | 16,831 |
| `LeverBeacon` | 785 | 23,791 |

`LeverVaultFactory`'s initcode is 7,792 bytes, inside EIP-3860's 49,152. The registered address
is a 279-byte `BeaconProxy` in front of that implementation.

One test probe exceeds EIP-170: `FlapProbe` (30,081).
They are injected by `eth_call` state override and are never deployed, so the limit does not bind
them; the size gate in `scripts/test.sh` passes them through and fails on any deployable contract.
